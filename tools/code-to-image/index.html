The complete guide

Why render code in the browser

Carbon has been stuck since late 2024. Ray.so wants your email. Here's what a tool that runs in your tab gets you.

The upload problem nobody talks about

Every server-side code-to-image tool receives your snippet, renders it on their machine, sends back a URL. For most code, that's fine. For anything sensitive, an unreleased API, internal tooling, client work under NDA, it's a leak waiting to happen.

Client-side rendering flips the model. The image is drawn in your tab. Nothing leaves your machine. The privacy badge at the top of this page proves it (it's a real counter, not a slogan).

How canvas rendering works

The browser ships with a 2D drawing API that's been there since 2004. You create a <canvas> element, get a drawing context, then issue commands: fill a rectangle, draw text, set a font. The browser paints pixels to the canvas, and you can export the result as a PNG or SVG.

For text, the trick is measuring the width of each line and wrapping manually. For syntax highlighting, you tokenize the source first, then draw each token in its theme color.

Why this is faster than Carbon or Ray

Server tools need a round trip. You upload, they queue it, render, send back. Latency adds up. The browser round trip is zero. Every keystroke in the editor redraws the canvas in under 16ms (60fps). You see the result of every change instantly.

The same input that takes 2-4 seconds on a server tool renders here in 30ms.

What "embed code" actually does

When you click "Embed code," the tool generates an HTML snippet that loads your generated image on someone else's blog. The snippet includes a small, unobtrusive "made with asadfaizee" backlink.

It's the same viral loop that Carbon used to dominate with. Each embed is a tiny SEO boost. Opt-in, never required, easy to remove if you want.

When to use PNG vs SVG

PNG is raster. Fixed pixels, fixed size, looks identical everywhere. Best for Twitter, LinkedIn, Discord, anywhere that compresses images. SVG is vector. Scales infinitely, smaller file size for simple images, but social platforms often convert it back to PNG anyway.

Default to PNG. Use SVG for blog posts and documentation where you want zoomable text.

The 2x retina trick

When you download the PNG, the canvas is exported at 2x the display resolution. A 720x400 preview becomes a 1440x800 image. Text stays crisp on retina MacBook screens, iPhones, high-DPI Windows laptops. The file size is roughly double, but the quality is worth it.

You can verify this by downloading the same image twice, once at 1x and once at 2x. The 2x looks sharper. Always.

FAQ

Common questions

Does this upload my code?

No. The image is drawn on a canvas in your browser tab. No network requests, no upload step. The badge at the top of the page is a real counter; it stays at 0 forever.

What languages work?

JavaScript, TypeScript, Python, Rust, Go, Java, C, C++, C#, Ruby, PHP, SQL, Bash, JSON, HTML, CSS, and Markdown. The highlighter is pattern-based, so coverage is solid for the common cases. Auto-detect picks the best match if you're not sure.

How is this different from Carbon or Ray.so?

Carbon has been stagnant since late 2024. Ray.so is actively maintained but gates some features behind a login. This tool is free, login-free, runs offline, supports both code and Markdown in one place, and is one HTML file you can save to disk and use without internet.

Can I use the generated images commercially?

Yes. The images are yours, no watermark, no attribution required. The optional embed code for blog posts does include a small backlink, but you can delete it.

What resolution do I get?

The PNG export is 2x the display size. A 720px wide preview exports at 1440px. Crisp on retina displays, slightly larger file size than 1x. For SVG, it's vector and scales infinitely.

Does this work offline?

Yes. Save the page (Ctrl+S / Cmd+S) to your filesystem. Open it from disk. The fonts are the only dependency, and those come from the local cache after the first load.
