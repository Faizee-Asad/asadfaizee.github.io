How to read a regex (and why the explainer matters)

Regex looks like line noise until you learn to read it left to right. Here's the mental model.

Regex is a tiny language

A regex is a pattern that describes a set of strings. The engine reads your pattern character by character, and at each position in the input, it tries to match. If the engine reaches the end of your pattern, you have a match.

Most "magic" of regex is just shortcuts. \d means "any digit," but it's the same as [0-9]. \w is "any word character," which is the same as [a-zA-Z0-9_]. The shortcuts exist because typing \d is faster than [0-9].

Quantifiers control repetition

After a character or group, a quantifier says "match this many times." * means 0 or more, + means 1 or more, ? means 0 or 1. {3} means exactly 3, {3,5} means 3 to 5.

The greedy default is fine for most cases. The engine tries the longest match first, then backtracks if the rest of the pattern fails. Lazy quantifiers (*?, +?) flip the order: shortest match first, expand if needed.

Capture groups extract data

Parentheses (...) do two things: group parts of the pattern together, and capture the matched text. The first group is $1 in the replacement, the second is $2, and so on. Named groups let you use names instead of numbers.

If you only need grouping, not capture, use (?:...). It's faster (the engine skips saving the captured text) and your group numbering stays clean.

Anchors are about position, not characters

^ and $ don't match characters, they match positions. ^ is the start of the input (or the start of a line, with the m flag). $ is the end. \b is a word boundary, the spot between a word character and a non-word character.

Common bug: a pattern like ^https:// doesn't match a URL in the middle of a paragraph. Drop the ^ and it'll match anywhere. Or use the m flag to make ^ work line by line.

Why a tester helps more than a cheatsheet

You can read every cheatsheet on the web and still not get regex. The patterns are simple in isolation, but the way the engine combines them is where the complexity lives. A good tester shows you exactly which characters matched, in which order, with which groups.

The explainer on this page walks the pattern left to right, the same way the engine does. Once you've matched the explainer's output to a few real patterns, reading new ones gets 10x easier.

Privacy: why regex tools leak

Regex patterns often contain the data they were built to extract. If you're testing a pattern against a real customer list, real log lines, or a real API payload, that data should not leave your machine. Server-side regex testers receive both your pattern and your test string.

This tool uses the browser's built-in RegExp engine. Your pattern and your test data stay in the tab. The privacy badge at the top of this page is a real counter, and it stays at 0.

FAQ

Common questions

Does this send my regex or test data to a server?

No. Everything runs in your browser tab using the browser's built-in RegExp engine. The privacy badge at the top of the page is a real counter, and it stays at 0 forever.

What regex flavor does this use?

JavaScript's RegExp. Compatible with PCRE for most common patterns. Supports named groups, lookaheads, and lookbehinds. The only edge case is some atomic group syntax (JavaScript doesn't support (?>...)).

How does the explainer work?

The pattern gets tokenized into atoms. Each atom (character, character class, quantifier, group, anchor) gets a plain-English label. The explainer walks the pattern left to right, in the same order the engine evaluates it.

Can I do find and replace?

Yes. Switch to the Replace tab. The replacement string supports $1, $2, $& (full match), $` (text before match), and $' (text after match).

Why no match highlight in the input?

The input is a textarea. Browsers don't let you style content inside a textarea. The matches are highlighted in a separate layer behind the textarea (same font, same width, same scroll position). The cursor stays in the textarea where you can type.

What about regex flags?

All of them. g (global, find all), i (case insensitive), m (multiline), s (dotall, dot matches newlines), u (unicode), y (sticky, match from lastIndex). Toggle them with the buttons above the pattern.
